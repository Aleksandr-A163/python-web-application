# Тестирование телефонного справочника

Учебный проект по автоматизированному тестированию консольного телефонного
справочника на Python. Основная цель работы — проверить ключевые операции
приложения, обработку некорректных данных, файловое хранение и взаимодействие
компонентов MVC.

Исходное приложение создано на основе проекта
[python-phonebook-mvc](https://github.com/Aleksandr-A163/python-phonebook-mvc).
Для тестирования используются `pytest` и `pytest-cov`.

## Что проверяют тесты

Набор содержит 35 тестов и охватывает все основные сценарии справочника:

- добавление контакта и автоматическое назначение ID;
- поиск по имени, телефону, комментарию, ID и общему запросу;
- поиск без учёта регистра и поиск несуществующего контакта;
- изменение отдельных полей контакта;
- сохранение даты создания и обновление даты изменения;
- удаление существующего контакта и удаление по неверному ID;
- группировка и сортировка контактов по первой букве имени;
- работа и очистка кэша поиска после изменения данных;
- создание воспроизводимых тестовых контактов генератором;
- команды контроллера, подтверждение несохранённых изменений и выход;
- вывод контактов и сообщений через консольное представление;
- успешный запуск приложения и восстановление после ошибки чтения файла.

## Проверка файлового слоя

Тесты работают с временными каталогами `pytest` и не изменяют настоящий
`contacts.json`. Проверяются:

- сохранение контактов в JSON и последующее чтение без потери данных;
- корректное восстановление дат создания и изменения;
- совместимость со старыми файлами, в которых отсутствуют даты;
- открытие несуществующего файла как пустого справочника;
- некорректный JSON и неверная структура данных;
- ошибки доступа при чтении и записи файла.

## Проверка исключений и граничных условий

Тесты подтверждают работу пользовательских исключений:

- `ValidationError` — пустое имя или телефон, пустой запрос, неверный ID;
- `ContactNotFoundError` — контакт с указанным ID отсутствует;
- `InvalidDataFormatError` — повреждённый JSON, неверные поля или повторяющиеся ID;
- `FileReadError` — файл невозможно прочитать;
- `FileWriteError` — файл невозможно сохранить.

Отдельно проверяются пустой контакт, нулевые и отрицательные значения,
несуществующие записи, неправильные типы данных и файлы старого формата.

## Параметризованные тесты

С помощью `@pytest.mark.parametrize` проверяются различные варианты:

- кириллических, составных и латинских имён;
- телефонных номеров с пробелами, скобками и дефисами;
- поисковых запросов в разных регистрах;
- пустых обязательных полей;
- неверных ID и дат;
- повреждённого содержимого JSON;
- некорректного количества генерируемых контактов.

## Применённые техники тест-дизайна

Количество тестов сокращено без потери функционального покрытия:

- **классы эквивалентности** — из групп однотипных корректных и некорректных
  значений выбраны репрезентативные примеры;
- **анализ граничных значений** — проверяются значения непосредственно на
  границе допустимого диапазона и рядом с ней, например `0` и `1`;
- **таблицы решений** — связанные варианты ошибок ввода и файловых операций
  проверяются в одном тестовом сценарии;
- **переходы состояний** — CRUD-сценарий последовательно проверяет создание,
  поиск, изменение, сохранение, удаление и повторное открытие контакта;
- **параметризация** — разные значимые форматы данных проверяются одним тестом
  без дублирования подготовительного кода.

В результате исходный набор из 68 случаев сокращён до 35, при этом покрытие
всех рабочих модулей осталось равным 100%.

## Структура проекта

```text
python-phonebook-tests/
├── tests/
│   └── test_phonebook.py   # все автоматизированные тесты
├── controller.py           # контроллер приложения
├── exceptions.py           # пользовательские исключения
├── generator.py            # генератор тестовых контактов
├── main.py                 # точка входа
├── model.py                # контакты, справочник и файловый слой
├── view.py                 # консольное представление
├── pytest.ini              # настройки поиска тестов
└── requirements-dev.txt    # pytest и pytest-cov
```

## Установка и запуск

Требуется Python 3.10 или новее.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Подробный вывод каждого теста:

```bash
python -m pytest -v
```

## Проверка покрытия

```bash
python -m pytest \
  --cov=controller \
  --cov=exceptions \
  --cov=generator \
  --cov=main \
  --cov=model \
  --cov=view \
  --cov-report=term-missing \
  --cov-fail-under=100
```

Текущий результат:

```text
35 passed
Total coverage: 100.00%
```

Все рабочие модули проекта покрыты тестами на 100%.
