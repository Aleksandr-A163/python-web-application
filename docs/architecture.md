# Архитектура приложения

## Цель

Проект развивается из консольного телефонного справочника в приложение с двумя
пользовательскими интерфейсами: CLI и HTTP. Оба интерфейса используют одну
предметную модель и не содержат собственной реализации операций с контактами.

Публичные URL, JSON-схемы и HTTP-статусы первой версии зафиксированы в
[`http-contracts.md`](http-contracts.md).

## Границы компонентов

```text
CLI (main.py, phonebook/cli/)
                    \
                     -> PhoneBook, Contact (phonebook/model.py)
                    /
Web (app.py, phonebook/web/)

FileReader, FileWriter (phonebook/model.py) -> contacts.json
```

- `phonebook/model.py` содержит сущность `Contact`, коллекцию `PhoneBook` и операции над
  контактами. Доменный код не зависит от FastAPI, Jinja2 или консольного ввода.
- `main.py` остаётся точкой сборки и запуска консольного приложения.
- `app.py` станет точкой сборки ASGI-приложения и будет подключать HTTP-роутеры.
- `phonebook/cli/` содержит сборку, контроллер и представление CLI.
- `phonebook/web/` содержит сборку и HTML-представления FastAPI.
- `phonebook/web/api/` содержит JSON API и вложенный роутер контактов.
- `phonebook/web/schemas/` содержит Pydantic-схемы HTTP-контрактов. Эти схемы не
  заменяют доменную сущность `Contact`.
- `phonebook/web/templates/` содержит базовый и дочерние Jinja2-шаблоны.

## Направление зависимостей

Интерфейсы зависят от предметной модели, но предметная модель не знает об
интерфейсах:

```text
FastAPI / CLI -> PhoneBook -> Contact
FastAPI / CLI -> FileReader / FileWriter
```

Модули `phonebook/model.py`, `phonebook/exceptions.py` и
`phonebook/generator.py` не должны импортировать веб-модули, FastAPI или Jinja2.

## Сборка приложений

Проект имеет две независимые точки входа:

- `python main.py` запускает существующий CLI;
- `uvicorn app:app` запускает веб-приложение.

Создание `PhoneBook`, чтение `contacts.json` и подключение роутеров выполняются
в точках сборки, а не внутри доменной модели. Это позволяет тестам передавать
изолированный справочник без обращения к рабочему файлу.

## Состояние и хранение

На первом этапе веб-приложение загружает контакты из `contacts.json` в один
экземпляр `PhoneBook`. Обработчики получают этот экземпляр через зависимость
FastAPI. Такой подход достаточен для учебного однопроцессного приложения и
позволяет изолировать состояние в тестах.

Изменяющие операции должны сохранять состояние через `FileWriter`, но роутеры
не должны открывать файл напрямую. Файловый путь и объекты хранения передаются
при сборке приложения. Переход на базу данных в будущем не должен менять
доменную сущность или HTTP-контракты.

Запуск нескольких worker-процессов до появления общего хранилища не
поддерживается: у каждого процесса была бы собственная копия `PhoneBook`.

## Обработка ошибок

Домен продолжает сообщать об ошибках собственными исключениями:

- `ValidationError` преобразуется веб-слоем в клиентскую ошибку;
- `ContactNotFoundError` преобразуется в HTTP 404;
- ошибки чтения и записи преобразуются в соответствующие ответы уровня
  приложения и не раскрывают внутренние детали файловой системы.

HTTP-исключения не используются внутри `model.py`.

## Планируемая структура

```text
python-web-application/
├── app.py
├── main.py
├── phonebook/
│   ├── __init__.py
│   ├── exceptions.py
│   ├── generator.py
│   ├── model.py
│   ├── cli/
│   │   ├── application.py
│   │   ├── controller.py
│   │   └── view.py
│   └── web/
│       ├── application.py
│       ├── dependencies.py
│       ├── pages.py
│       ├── api/
│       ├── schemas/
│       └── templates/
└── tests/
```

Корневые `main.py` и `app.py` являются стабильными точками запуска, а реализация
скомпонована внутри пакета `phonebook`.

## Архитектурные ограничения первого релиза

- существующий CLI и его тесты сохраняют обратную совместимость;
- бизнес-правила не дублируются в Pydantic-схемах и роутерах;
- API-роутеры не используют глобальный изменяемый список контактов;
- рабочий `contacts.json` не используется в автоматических тестах;
- база данных, асинхронный файловый ввод-вывод и многопроцессный запуск не
  добавляются до появления соответствующих требований.
