# HTTP-контракты

Документ фиксирует публичное поведение первой версии веб-приложения. Изменение
описанных URL, полей или кодов ответа после реализации считается изменением
контракта и должно сопровождаться обновлением тестов.

## Общие соглашения

- HTML-представления и JSON API подключаются отдельными роутерами.
- Все маршруты API имеют префикс `/api`.
- Роутер сущности `Contact` имеет префикс `/contacts`.
- JSON передаётся в UTF-8, даты имеют формат ISO 8601.
- Идентификатор контакта — положительное целое число, назначаемое сервером.
- Канонические collection URL оканчиваются `/`.

## HTML-представления

### Главная страница

```http
GET /
```

- имя маршрута: `index`;
- успешный статус: `200 OK`;
- тип содержимого: `text/html`;
- шаблон: `index.html`;
- назначение: главная страница телефонного справочника.

### О проекте

```http
GET /about/
```

- имя маршрута: `about`;
- успешный статус: `200 OK`;
- тип содержимого: `text/html`;
- шаблон: `about.html`;
- содержимое: назначение сайта и информация о разработчике.

Обе страницы наследуют `base.html`. Навигация формирует ссылки через
`url_for("index")` и `url_for("about")`, а не через жёстко записанные URL.

## Схемы контакта

### `ContactCreate`

Тело запроса на создание контакта:

| Поле | Тип | Обязательное | Правило |
|---|---|---:|---|
| `name` | string | да | после удаления внешних пробелов не пустое |
| `phone` | string | да | после удаления внешних пробелов не пустое |
| `comment` | string | нет | значение по умолчанию — пустая строка |

Клиент не передаёт `id`, `created_at` и `updated_at` — эти значения назначает
предметная модель.

Пример:

```json
{
  "name": "Иван Иванов",
  "phone": "+7 999 123-45-67",
  "comment": "Коллега"
}
```

### `ContactResponse`

Представление контакта в ответах:

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | положительный идентификатор |
| `name` | string | имя контакта |
| `phone` | string | номер телефона |
| `comment` | string | комментарий, возможно пустой |
| `created_at` | string, date-time | дата создания в ISO 8601 |
| `updated_at` | string, date-time | дата последнего изменения в ISO 8601 |

Пример:

```json
{
  "id": 1,
  "name": "Иван Иванов",
  "phone": "+7 999 123-45-67",
  "comment": "Коллега",
  "created_at": "2026-09-06T12:00:00",
  "updated_at": "2026-09-06T12:00:00"
}
```

### `ContactUpdate`

Тело запроса частичного изменения может содержать `name`, `phone` и
`comment`. Должно быть передано хотя бы одно поле. Переданные `name` и `phone`
не могут быть пустыми после удаления внешних пробелов.

## API контактов

### Прочитать список

```http
GET /api/contacts/
```

- успешный статус: `200 OK`;
- тело ответа: JSON-массив объектов `ContactResponse`;
- пустой справочник возвращает `[]` и статус `200`;
- порядок первой версии совпадает с порядком контактов в `PhoneBook`.
- необязательный параметр `query` выполняет регистронезависимый поиск по ID,
  имени, телефону и комментарию;
- пустой поисковый запрос возвращает `422 Unprocessable Content`.

### Прочитать контакт

```http
GET /api/contacts/{contact_id}
```

- параметр `contact_id`: положительное целое число;
- успешный статус: `200 OK`;
- тело ответа: объект `ContactResponse`;
- отсутствующий контакт: `404 Not Found`.

Пример ответа `404`:

```json
{
  "detail": "Контакт с ID 999 не найден."
}
```

### Создать контакт

```http
POST /api/contacts/
Content-Type: application/json
```

- тело запроса: `ContactCreate`;
- успешный статус: `201 Created`;
- тело ответа: созданный `ContactResponse`;
- созданный контакт сразу доступен в списке и по своему ID;
- после успешного изменения актуальное состояние сохраняется через
  `FileWriter`.

### Частично изменить контакт

```http
PATCH /api/contacts/{contact_id}
Content-Type: application/json
```

- тело запроса: `ContactUpdate`;
- успешный статус: `200 OK`;
- тело ответа: обновлённый `ContactResponse`;
- отсутствующий контакт: `404 Not Found`;
- после успешного изменения состояние сохраняется через `FileWriter`.

### Удалить контакт

```http
DELETE /api/contacts/{contact_id}
```

- успешный статус: `204 No Content`;
- тело успешного ответа отсутствует;
- отсутствующий контакт: `404 Not Found`;
- после успешного удаления состояние сохраняется через `FileWriter`.

Для `POST`, `PATCH` и `DELETE` приложение восстанавливает предыдущее состояние
`PhoneBook`, если запись файла завершилась ошибкой.

## Ошибки

| Ситуация | Источник | HTTP-статус |
|---|---|---:|
| Неверный JSON или тип поля | FastAPI/Pydantic | `422 Unprocessable Entity` |
| Пустые `name` или `phone` | валидация входной схемы | `422 Unprocessable Entity` |
| Неположительный `contact_id` | валидация параметра пути | `422 Unprocessable Entity` |
| Контакт отсутствует | `ContactNotFoundError` | `404 Not Found` |
| Ошибка чтения начального файла | `FileReadError` | ошибка запуска приложения |
| Ошибка сохранения | `FileWriteError` | `500 Internal Server Error` |

Веб-слой преобразует доменные исключения в HTTP-ответы. Модули предметной
модели не создают `HTTPException` и не зависят от FastAPI.

## Состояние и тестируемость

- Рабочее приложение загружает `contacts.json` при сборке приложения.
- Один экземпляр `PhoneBook` используется всеми обработчиками одного процесса.
- Роутеры получают `PhoneBook` и механизм сохранения через зависимости.
- Автоматические тесты подменяют эти зависимости и не читают и не изменяют
  рабочий `contacts.json`.
- API не использует отдельный глобальный список и вызывает методы `PhoneBook`.

## Не входит в текущую версию

- расширенная фильтрация, сортировка и пагинация;
- аутентификация и авторизация;
- база данных;
- безопасная синхронизация нескольких worker-процессов;
- версионирование URL вида `/api/v1`.
